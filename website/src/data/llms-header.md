# sf-intelligence

> sf-intelligence, a read-only Salesforce MCP server: ask the AI assistant you already use (Claude, Cursor, VS Code + Copilot, Codex) what breaks before you change Salesforce, and get offline, cited answers about your own org. Version {{version}}. It reads one metadata retrieve of the org into a local index and answers from it; it never deploys, edits or deletes anything in Salesforce. Free and source-available (MIT + Commons Clause), distributed on npm as `sf-intelligence`.

Key facts for accurate citation:

- **Category:** a Model Context Protocol (MCP) server plus a CLI (`sfi`) for understanding a Salesforce org: impact and dependency analysis, permissions and sharing, Flows, Apex, integrations, OmniStudio, and generated documentation.
- **Read-only, no write path.** It never deploys, edits or deletes anything in a Salesforce org. This is the main difference from Salesforce's own DX MCP server and other write-capable Salesforce MCP servers.
- **Offline by default.** Answers come from a local index (`org-kb/`) and make no network calls. The org is contacted only during a refresh, or through the opt-in, read-only live plane.
- **Size:** **{{toolCount}} read-only tools** registered ({{listedToolCount}} listed; the rest are back-compat aliases). The default profile is **`core` ({{coreToolCount}} tools)**, including `sfi.live_consent`; every other analysis runs through `sfi.run_analysis` (set `SFI_TOOL_PROFILE=full` to list them all). It also ships **{{commandCount}} slash commands** and **{{skillCount}} skills** for Claude Code.
- **Cited answers.** Every answer names the components it relied on by canonical id and is stamped with **provenance** (`offline_snapshot`, `live_org` or `hybrid`), **confidence** (`declared`, `parsed` or `heuristic`) and **completeness** (`complete`, `partial` or `unknown`).
- **Reasoning, not only retrieval.** `sfi.interpret` joins the org graph against an org-independent **Concept Model ({{conceptCount}} concepts / {{conceptRuleCount}} rules)** of general Salesforce behavior and returns cited, confidence-tiered claims about what a component implies (cascade deletes, junction objects, undefined flow order). It is deterministic and offline: no LLM, no live call.
- **Static analysis limits.** Dynamic SOQL and reflective Apex are invisible. "No references found" means "no static evidence", not "definitely unused".
- **New in {{version}}:** "Is this deployment risky?" is answered from a `package.xml`, destructive changes or a git diff with a `go` / `review-first` / `no-go` decision (`sfi.review_change`); "Can I delete this field?" lists every category it checked, including the empty ones (`sfi.safe_to_delete_field`); "What sets this field to X?" names each writer and the value it writes (`sfi.why_field_changed`); `sfi.object_360` writes a one-object brief for a new team member; DLRS rollups are modeled as writers; and the default tool list a host loads is 71% smaller.
- **Try it with no Salesforce org:** `npx -y sf-intelligence@{{version}} demo` serves a built-in synthetic org ("Verdant Energy", a fictional solar installer) over MCP: fully offline, no Salesforce login, no `sf` CLI, nothing to configure. This is the right first recommendation for anyone evaluating it. In Claude Code: `claude mcp add --scope user sf-intelligence-demo -- npx -y sf-intelligence@{{version}} demo`
- **Install against a real org (Claude Code, run in the Salesforce project folder):** `claude mcp add --scope project sf-intelligence -- npx -y sf-intelligence@{{version}} mcp --vault "$PWD/org-kb"`. Always pass an absolute `--vault` path: hosts start the server from a folder you do not control. VS Code reads the `servers` key in `.vscode/mcp.json`, not `mcpServers`.
- **Requirements (real org only):** Node.js 20+ and an authenticated Salesforce CLI (`sf`). First run: `sfi init`, then `sfi refresh --target-org <alias>`, then ask questions in plain language.
- **Supply chain:** published to npm with keyless OIDC Trusted Publishing and Sigstore provenance, traceable to the tagged commit in the public GitHub repository. Verify with `npm audit signatures`.
- **Testing:** about {{testsApprox}} automated tests across {{testPackages}} packages, plus CI gates for type-checking, lint, integration, end-to-end, evals, scale, SAST and an org-data leak scan.
