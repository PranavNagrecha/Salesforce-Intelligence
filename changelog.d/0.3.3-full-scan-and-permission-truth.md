### Fixed
- **Four org-wide inventories reported an alphabetical first page as a complete org.** `org_overview` ranked "top objects by inbound reference" and "top Apex classes" over the alphabetically-first 500 nodes and computed `automationSummary.activeRatio` as a 500-node numerator against a `COUNT(*)` denominator; `integration_map` divided its row budget eight ways and returned ~13 rows per category in an output type with no truncation field at all; `endpoint_catalog` advertises "every URL / endpoint" and reported `summary.totalEndpoints` from a 500-per-category scan; `test_coverage_gaps` built both its class corpus and its test-class set from one 500-row page, so a test class sorting past position 500 was invisible and its callers were reported `uncovered`. All five tools (including `generate_admin_handbook`) now scan to exhaustion through the existing `scanAllNodesOfTypes` helper, and `full-scan-adoption.test.ts` fails if a single-page corpus scan reappears in any of them.
- **`test_coverage_gaps` returned `gaps: []`, `totalGapsCount: 0` for a `classFilter` naming ids that are not in the vault** — an unchecked zero indistinguishable from a clean bill of health. Unknown ids are now named in `notFoundClassIds` and disclosed in `boundaries[]`.
- **`compare_profile_across_vaults` reported "0 object / field / Apex permission drift" from three node properties the Profile extractor never writes.** It read `properties.objectPermissions` / `fieldPermissions` / `apexClassAccesses` — the extractor writes counts, not grants — so the tool fabricated a confident measured zero. Grants are now read from `grantedBy` edges, as `compare-components.ts` already did. `extractGrantMap` also dropped every `userPermissions` entry to a `typeof entry === 'object'` guard against what is really a `string[]`, reporting 8 real differences as 0. The now-populated arrays are paged through the shared `paginateSection` cursor with the byte budget derived from `toolLocalPayloadBudgetBytes()`, so the tail is reachable rather than silently trimmed.
- **`why_cant_user_see_record` returned a confident `restricted` hard deny for a profile or permission set that is not in the vault at all** — a deny computed from a container nobody read, stated as a measured fact. A caller-supplied container that cannot be read now yields `unknown` with the gap named. PermissionSetGroup MEMBER ids are deliberately excluded from that rule: they are synthesized from bare names and are routinely unextracted, so those misses are disclosed on the PermissionSetGroup step and the verdict still resolves.
- **`sfi refresh`'s side-build swap could throw a raw errno out of the CLI.** Every filesystem call in the swap is now inside the catch, the drifted inline lock-message regex is replaced by the classification `GraphError.kind` already carries, and the failure message states what actually happened: the database was not replaced, answers are STALE not broken, whether the scratch rebuild was really cleaned up, and that `graph/resolve-index.json` beside the database was overwritten from the discarded build and should be deleted. **Not fixed, and stated rather than papered over:** on Windows a refresh still cannot swap a vault database while a client holds it open — that needs generation-named database files, which is a larger design than this release.
- **`sfi vault anonymize`'s containment rails compared paths case-sensitively**, so on the case-insensitive filesystems this ships on (NTFS, default APFS) an `--out` spelled in a different case passed both rails and wrote the redacted copy inside the live vault. The rails now test containment across several path spellings and refuse if ANY of them reports containment in EITHER direction, so the guard can only ever tighten. A symlinked vault — this project's own layout — is covered explicitly by test.
