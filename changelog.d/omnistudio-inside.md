### Added
- **OmniStudio is modeled from the inside.** Every OmniScript, Integration Procedure, FlexCard and DataMapper is parsed into its elements through one element catalog (canonical types, every alternative spelling, runtime roles — generated into `docs/omnistudio/element-catalog.md`). New edges: any element naming a `remoteClass` calls that Apex class (`callsApex`, with methods and call sites — Apex called only from OmniStudio no longer looks dead); DataMappers read and write individual fields (Extract, Turbo, Load — a Load's object write says create or upsert); an Integration Procedure Delete Action deletes the objects it names; a FlexCard SOQL data source reads its object and fields. Cross-references now land on the version that runs (an IP's `isActive` is the runtime switch; a DataMapper's `active` flag is not), so impact and dependency walks cross from a screen into its server code.
- **Ten OmniStudio tools:** `omni_model`, `omni_save_trace` (does each answer reach a field?), `omni_prefill_trace` (does it come back on reopen?), `omni_dead_references`, `omni_version_diff`, `omni_edit_block_audit`, `omni_completion_audit`, `omni_form_spec`, `omni_path_simulator` (now with `DEAD_END_SECTION`: answers that add a section while its entry step hides itself, found by a satisfiability search over the step's rule expanded through the script's formulas) and `omni_changed_since` (semantic diff of what changed since a snapshot).
- **Four audit tools:** `record_delete_impact` (cascade / orphan / restrict per lookup, delete guards, who can delete — including generic Apex delete helpers resolved at their call sites), `persona_unused_grants` (object and field permissions nothing a persona can run uses; never UNUSED when it cannot tell), `live_verify` (re-check one vault claim against the org, read-only and consent-gated) and `how_to_see` (the Setup click path to see a component).
- **`sfi run <tool> --json --<arg> <value> … --vault <path>`** calls any tool from a script through the MCP dispatch path; arguments are typed from the tool's own schema.
- **`--vault <path>` means one thing everywhere** — `run`, `status`, `doctor`, `selftest`, `snapshot`, `refresh`, `feedback export`, `gaps report`, `review-change` — and accepts the `org-kb` folder or the folder that holds it. `gaps report --vault` counts only that vault's gaps.
- **App scope for counting tools.** `picklist_integrity_scan` and `doc_coverage_report` accept `scope` {namePrefixes, namespaces} (default: `org-kb/config/app-scope.json`, else the OmniStudio `appScope`) and answer with the scoped number, the org-wide number beside it as a labelled contrast. `picklist_integrity_scan` now reports how every picklist is restricted (global value set / inline restricted / inline unrestricted / unknown).
- The field extractor records a picklist's `restricted` flag and a lookup's `deleteConstraint`; snapshots record runtime switches and a hash of each OmniStudio source file.
- **Managed-package (Vlocity) OmniStudio.** A Vlocity Build Tool DataPack export placed under `org-kb/source/vlocity/` (OmniScript, IntegrationProcedure, DataRaptor and VlocityCard DataPacks, with their sibling files; the `%vlocity_namespace%` placeholder or a real `vlocity_cmt` / `vlocity_ins` / `vlocity_ps` / `omnistudio` prefix) is converted to the native component's shape and extracted by the same code as native metadata — same node ids, edges, graph resolution, and every OmniStudio tool. Nodes carry `sourceFormat: vlocity-datapack` and cite the DataPack file; a snapshot fingerprints the whole DataPack folder, so `omni_changed_since` sees an edit to a sibling file; other DataPack types are disclosed as skipped, and the refresh never deletes an export. OmniStudio tools say in `trust.limitations` when an installed Vlocity package has no export (its components are missing, not absent) and how many components came from one. Export recipe in `docs/configuration.md`.
- **Apex that runs OmniStudio is a caller in the graph.** `<ns>.IntegrationProcedureService.runIntegrationService('Type_SubType', …)` and `<ns>.DRGlobal.process(…, 'Bundle')` / `processObjectsJSON` with a literal key (namespace `omnistudio`, `vlocity_cmt`, `vlocity_ins` or `vlocity_ps`) become `dispatchesOmniAction` edges from the Apex class (`via: apex`), resolved onto the version that runs — so usage, impact and unused-component answers count Apex callers, and an IP called only from Apex no longer looks unused. The call no longer mints a phantom `ApexClass:IntegrationProcedureService` / `DRGlobal` or a `CustomField:<ns>.<Class>` read. A key built at runtime is not guessed. New concept `apex-runs-omnistudio`.
- **The managed runtime's IntegrationProcedureService is an IP call, not Apex.** A Remote Action on `<ns>.IntegrationProcedureService` dispatches to the Integration Procedure its method names (`dispatchesOmniAction`, `via: runtime-service`); the save and prefill traces follow it into that IP, and `integration_procedure_chain` lists it as an `integration-procedure` endpoint.
- Concepts and rules for the new semantics (DataMapper writes, remote Apex calls, Edit Block delete wiring, IP Delete Actions, lookup delete behavior, picklist restriction, dead-end sections, DataMapper `active` not being a runtime switch, managed-package OmniStudio records).

### Changed
- `integration_procedure_chain` walks steps nested in blocks, classifies every spelling through the catalog, names the active version of a multi-version target (others listed), resolves Apex calls to ApexClass nodes, reports Delete Actions, and sums what the chain reads, writes and deletes. Its and `omniscript_flow`'s Apex disclosure now says what is and is not modeled.
- The OmniStudio formula evaluator computes `CONTAINS` and returns computed values, not only truth.
- The Integration Procedure extractor compares element types through the catalog, so an `HTTP Action` callout is recorded like a `Rest Action`.
- An Apex class OmniStudio calls by name that the vault does not hold says what that means and how to tell a missing class from a package service.
- The five OmniStudio component tools share ONE native-vs-managed-package disclosure, which now says where managed-package components come from instead of that they are not extracted.
- Every tool the release added is registered in the high-fan-out inventory with a real-org probe (the 0.3.3 registration backlog is empty).
- Question routing keeps the older tools reachable next to the new OmniStudio vocabulary: "which OmniScripts exist" reaches the inventory tool (`list_components`, through a component-family card that dilutes nothing else), and "would the platform block deleting this field" still reaches `safe_to_delete_field`.

### Fixed
- **A `--with-tooling-api` refresh that could not capture permission dependencies said so nowhere.** A sign-in failure stopped the pass before the capture without naming it, an enrichment error hid the capture line, and `--staged` dropped the flag. The summary now prints a WARNING naming the cause on every path, and the refresh ends `partial`.
- **A copied vault could refresh the vault it was copied from.** A config whose `vaultRoot` names another folder is now refused by every command that writes to the vault, with the exact fix.
- OmniStudio cross-references no longer dangle onto phantom stubs with a "retrieve it" remedy; DataMapper input paths no longer mint phantom objects; an inactive DataMapper is no longer treated as dead; Edit Block `deleteIPKey` / `saveIPKey` are read.
- A `remoteClass` in a namespace containing an underscore (`vlocity_cmt.ClassName`) was dropped; it now links to its `vlocity_cmt__ClassName` component.
- **Consecutive offline refreshes are idempotent for Report / Dashboard coverage.** A refresh that pulled no reports read the previous manifest's capped-retrieve evidence but did not write it on, so the next `--no-pull` refresh — or the final tier of a staged build — reported Report / Dashboard as `pending` where a single refresh of the same source reported them captured.
- A key dropped at a DataMapper **Load** now names, in its near-miss suggestion, the field that item would have written (it was always empty; a Transform's already did).
- "Pull up every formula that **references** Amount__c" / "which formulas are **referencing** X" routed nowhere: the formula-reference rule matched only the bare verb. They now route to `find_formula_references`.
- **Routing honesty.** "Run automation risk for regression" / "execute the flow audit" were refused as requests to EXECUTE automation — a run verb on an analysis name is now a read (a run of the flow itself is still refused). Out-of-scope asks that slipped into low-confidence tool routes now get the honest out-of-scope answer: another platform's own data ("how many SAP tables"), rating people, purchasing decisions, general knowledge. A funnel-only (advisory) route now also requires the product to know a third of the user's words, so a gibberish question carrying one Salesforce word stays unrouted. "Resolve the component named X" routes to the resolver.
- **No phantom class from Schema describe chains.** `Schema.SObjectType.Account.getRecordTypeInfosByName()` (and `….fields.Name.getDescribe()`) minted a `callsApex ApexClass:Account` / `ApexClass:Name` edge in every org using the idiom; the token in a describe chain is an object or field name, never a class.
- "Which orgs in our fleet have drifted most from the baseline?" reaches `fleet_drift_ranking` first again (it was ranked under `fleet_find`), and "what flows can the guest user run" keeps `user_ability` in the shortlist.
